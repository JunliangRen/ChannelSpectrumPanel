# Channel Spectrum panel 0.17.2 深入静态分析

日期：2026-11-16。范围：原版 x86 DLL 的水平频率轴、向上增长柱体路径，重点为双声道镜像、幅度和峰值。本文是逆向分析记录，不是作者源码，也不是移植实现。

## 1. 样本、方法与结论边界

样本：`foo_uie_vis_channel_spectrum.dll（用户提供的本地样本，不随仓库分发）`。

- 版本字符串：0.17.2；文件大小：241664 字节；PE Machine：0x14c；ImageBase：0x10000000。
- SHA256：`e5bc0405fd9da2a59d9889fffc6fc21f8e9da71dc972d68c5e5218794a038c4b`。
- 方法：PE 元数据及对话框资源解析、x86 反汇编、调用参数跟踪、x87 浮点栈代数推导、设置读写交叉引用。
- 没有加载执行 DLL、没有打开或修改 foobar2000 设置，没有编写移植代码。
- 地址全部为此样本首选基址下的 VA，RVA = VA - 0x10000000。不是当前进程地址。
- 汇编事实、代数还原、运行时效果验证是不同层次；本文的公式属于静态还原，尚无逐帧或逐像素对照结果。

结论：已把 Mirror/Reverse 两种控制、声道分区、线性频率映射、带自适应锚点的对数映射、四种幅度变换和峰值参数链连接起来。对正常尺寸、两个声道、Rotate=0 的目标样式，已形成可供后续实现使用的行为规格。极窄窗口、初始化 bin 0 的浮点特殊值、所有旋转和抗锯齿分支仍需单独核对，不能宣称全插件已完整还原。

## 3. 左右镜像与频率坐标

### 3.1 设置到对象字段

以下 cfg 指配置对象，obj 指运行时面板对象；偏移不是文件格式绝对偏移。

| UI 设置 | 控件 ID / 对话框 | cfg 偏移 | obj 偏移 | 值或意义 |
|---|---|---|---|---|
| Channel Mode | 0x402 / 108 | +0x5C | +0xD04 | 0 Separate；1 Merge all；2 Specified below |
| Reverse freq-axis | 0x43B / 108 | +0x60 | +0xD00 | 0/1 |
| 指定声道 | 0x403 / 108 | +0x64 | +0xD08 | 与所选声道相关 |
| Rotate | 0x404 / 108 | +0x68 | +0xD0C | 此文重点为 0 |
| Reverse channel-pos | 0x43C / 108 | +0x6C | +0xD10 | 颠倒声道占用分区 |
| Range scale | 0x43D / 108 | +0x70 | +0xD14 | 1–1000；影响幅度，不是频率范围 |
| Spacing | 0x43F / 108 | +0x74 | +0xD18 | 柱间距；不同显示模式还有附加间隔 |
| Linear scale (frequency) | 0x444 / 108 | +0x8C | +0xD34 | 1 线性频率，0 自适应对数频率 |
| Direction | 0x44B / 116 | +0x114 | +0xDDC | 0 Mirror；1 Right；2 Left |
| Left / Right padding | 0x44C/0x44E / 115 | +0x118/+0x11C | +0xDE0/+0xDE4 | 整个图的左右留白 |
| Channel Padding | 0x450 / 116 | +0x120 | +0xDE8 | 相邻声道分区间隔 |

Direction 三个字符串按 Mirror、Right、Left 顺序加入下拉框，证据为 0x1001E4B3–0x1001E506；不是根据截图猜测枚举。

### 3.2 声道分区

令已减去左右 padding 的宽度为 W，实际显示声道数为 C，声道间距为 G，绘图 pitch 为 P。正常非退化尺寸下，0x1000B52B–0x1000B6B2 对每个声道分配：

`S = P * floor(floor((W - (C-1)*G) / C) / P)`

余量为 `E = W - (C-1)*G - C*S`。当余量绝对值至少 2 时，所有分区平移 `trunc(E/2)`，使整组栅格大致居中。正常 W、P、C 下 E 非负。

第 j 个物理分区左边界为 `L + j*(S+G) + shift`，右边界为其左边界加 S。开启 Reverse channel-pos 后，存入逻辑声道 `C-1-j` 的记录，未改变音频内容。

P 不应直接等同 Bar width：在 0x10003524–0x10003679，通常 P = Bar width + Spacing + 某些 Bar mode 路径的附加 1；Simple-line 模式另行处理。必须按显示模式保留这条换算。

### 3.3 低频在中间的条件

设逻辑声道序号为 c，从 0 起，Reverse freq-axis 为 r，Direction=Mirror 时：

- `(c+r) & 1 == 0`：走 0x1000B7DD 分支，从分区右侧向左增加频率；
- `(c+r) & 1 == 1`：走 0x1000BC99 分支，从分区左侧向右增加频率。

Direction=Right 强制进入第二条路径；Direction=Left 强制进入第一条路径。主绘图函数还会在 Reverse freq-axis 开启时交换强制方向值 1/2，见 0x100035FC–0x1000361C；不能只改镜像奇偶位而忽略强制方向。

在普通立体声、正常声道顺序、Reverse channel-pos 关闭时，目标组合是：

- Channel Mode = Separate；Direction = Mirror；Rotate = 0；
- Reverse freq-axis = 关闭；Reverse channel-pos = 关闭。

布局为：`高频 ← 左声道 ← 低频 | 低频 → 右声道 → 高频`。

两边是各自真实声道的频谱，不是把一边图像复制过去。开启 Reverse channel-pos 会改变分区归属，在 Mirror 模式下还会改变中心两侧是高频还是低频；不能把这个开关理解为只交换 L/R 标签。

### 3.4 频率的连续坐标与自适应对数映射

定义 FFT 大小 N，M=N/2，D=M-1，频谱索引 k。构造器循环 k=0..M-1；主绘图循环从 k=1 开始，所以 bin 0 不直接作为普通柱绘制。

在此 SDK 频谱语义下，物理频率通常为 `f_k = k*sampleRate/N`；最终显示的最高 bin 为 k=M-1，略低于 Nyquist。坐标端点归一化使用 D 而不是 M。

Linear scale (frequency) 开启时，频率距低频端的连续距离为：

`u(k) = S*k/D`。

关闭时，不是单纯把 `log(k)` 铺满屏幕。汇编先构造固定 1024 尺度的函数：

`Q(k) = 1024 * ln(1 + 1024*k/D) / ln(1025)`。

证据：0x1000B6E6–0x1000B755，常数 1024、1025 位于 0x1002C540、0x1002C538。

每个声道另有一个锚点索引 m，初始为 0。令：

`T = max(m, S*m/D)`

`F_m(k) = T + (S-T) * (Q(k)-Q(m)) / (1024-Q(m))`。

在正常有限浮点数路径上，构造器同时计算 `F_m(k-1)` 和 `F_m(k)`：

- 若两者间距大于 1 像素，走 0x1000B8E8 或 0x1000BD98 分支，将 m 更新为 k，并使用 `max(k, S*k/D)` 与前一 bin 对应值形成边界。
- 否则，使用上述锚定后的对数插值。
- Linear 开关走独立分支，直接使用 S*k/D，跳过这一混合结果。

因此低索引区可以保持每 bin 至少约一个像素的间距，高索引区再进行对数压缩，多个 bin 可合并到同一柱。锚点是构造坐标表时的状态，不是随音乐时间变化的动画状态。

以上为 x87 栈的代数还原。k=0 时会提前计算 Q(-1)，小 FFT 下可能触及无效对数；原版利用比较状态及随后不绘制 bin 0 的行为，不能直接把通用实数公式套在初始化步骤上。此边界未做指令执行对照，标记为待验证。S 太小、C=0 等退化情况也不属于这组简化公式的保证范围。

### 3.5 镜像、取整、栅格和合并

对正常正宽分区 [a,b]：

- 正向路径以 a 为原点增加 u；反向路径以 b 为原点减去 u。
- 0x10022880 向零截断；随后 IDIV/MUL 将某一边界对齐 P 的整数倍。负方向必须保留“先取负再向零截断”的顺序，不能随意换成 floor。
- 反向路径 0x1000BA2F–0x1000BA6A：先对前一 bin 的负向坐标按 P 量化，再加 b；当前端点至少向左扩展 P。
- 正向路径 0x1000BECC–0x1000BF04：当前 bin 的正向坐标按 P 量化，再加 a；前一端点至少向右扩展 P。
- 描述符为四个 DWORD，读取位置为 0x10004449–0x10004471：x1、绘制标志、x2、基线 y。第二项不是可直接当作 RECT.top 的普通坐标。
- 连续落入同一柱的 bin 会先累积最大幅度，直到描述符绘制标志非零时才绘制并清空累积值，见 0x10004349–0x10004477、0x10004918–0x10004922。

这也是精确复刻时不能用“每 bin 直接画一根柱”的原因。

## 4. 幅度计算

### 4.1 声道和 bin 聚合

读取的谱值为 float32。Separate 分支将输入声道映射到自定义显示顺序，再在同一绘制组中取最大值；Merge all 分支取各声道谱值的最大值；Specified below 分支跳过未选中的声道。已分析路径没有用平均值或 RMS 来代替这些 max 比较。

令 A 为当前绘制组累积的非负最大谱值。A 的物理归一化由宿主 FFT 模式决定，不能只凭此 DLL 断言 A=1 对应什么实际录音电平。

### 4.2 四种变换公式

令 R = Range scale（1–1000），K = `0.2309 * log2(M+1)`，q 为用于柱高的无量纲幅度。

| FFT mode | Logarithm scale | 静态还原的 q |
|---|---|---|
| old method，0 | 关闭 | `(100/R) * A/K` |
| old method，0 | 开启 | `(100/R) * ln(1+2*A)/ln(1+2*K)` |
| new method，1 | 关闭 | `(100/R) * max(0, 1 + (2/7)*log10(max(A,2^-17)))` |
| new method，1 | 开启 | `(100/R) * max(0, 1 + (1/4)*log10(max(A,2^-17)))` |

证据：0x100041DD–0x10004260 给出归一化因子；0x10004477–0x10004546 给出模式分支；常数 0.2309、2、2/7、1/4、2^-17 均已从 PE 数据区按 little-endian float64 解码。

关键解释：new method 即使没有勾选 Logarithm scale，也已经使用 log10；开关改变的是斜率。old method 则是另一套线性/ln(1+2A) 公式。不能把这个开关统一重写成“是否取对数”。R 越大，柱越矮；它是除数，不是增益百分比。

代数核对点：R=100 时，new method 的 A=1 得 q=1；A=0.01 时，开关关闭 q=3/7≈0.428571，开启 q=0.5。old method 的 A=K 时，两种模式均得 q=1。这些是公式一致性检查，不是实际音频测试。

### 4.3 转成柱高、颜色和屏幕坐标

H 为分析路径中绘图矩形的绝对高度：

- `height = trunc(H*q)`，0x10004546–0x10004551；
- `colorIndex = clamp(trunc(24*q), 0, 23)`，0x10004551–0x10004574；
- `y = baseline - height`，0x10004578–0x100045A0；
- 某些 Bar mode 路径将 y 按偶数对齐，再截到绘图区上边界，0x100045A4–0x100045B8。

q 本身没有在此处统一截到 1；超过图高后由坐标裁切。24 档索引还参与绘图路径，黑底灰白外观并不代表内部完全没有幅度颜色量化。

## 5. 峰值动画与参数

### 5.1 参数的完整来源

| 参数 | UI 输入 | cfg → obj | 范围 / 单位 |
|---|---|---|---|
| Refresh interval | 108:0x434 | +0x3C → +0xCF4 | 5–100 ms |
| Fall speed | 117:0x445 | +0x4C → +0xCB4 | 1–99，无量纲输入 |
| Hold time[10ms] | 117:0x447 | +0xBC → +0xCB8 | 输入 0–1000，乘 10 后存成 0–10000 ms |
| Show Peaks | 108:0x42D | +0x34 → +0xCF0 | 开关，特定显示模式还会屏蔽峰值绘制 |
| 派生加速度 a | 无独立控件 | +0xCB0 | 1/256 像素/更新²的离散步进系数 |

Hold 的乘 10 在 0x1001CEE1/0x1001CEF9；Fall speed 的限值在 0x1001CF45–0x1001CF63；Refresh 的限值在 0x1001F216–0x1001F232。

令 V=Fall speed，I=Refresh interval：

`a = trunc(128 * V * I / (500-I))`。

证据为 0x10020FBA–0x10020FF0，乘数 128.0 位于 0x1002C4E0。UI 的 I≤100 避免此公式接近 500 的奇点；手工导入非法配置是否另外被限制，本轮未完整审计。

构造默认值：I=14 ms，V=10，Hold=0 ms，FFT size=2048，Range scale=100，Direction=Mirror，Reverse freq-axis=0；这不代表用户当前保存的配置。派生 a 在构造期间先置 1，应用设置时按公式重算为 36，不应把构造占位值 1 当作运行稳态系数。

### 5.2 每声道、每绘制索引的状态

对象内有三组数组，声道 bank 步长 0x10：

- 指针 `obj+0x8C+0x10*c`：峰值坐标 P；
- 指针 `obj+0x1AC+0x10*c`：下落步进 v；
- 指针 `obj+0x2CC+0x10*c`：最近触顶时间 t0。

数组元素为 32 位数，位置内部保留 8 位小数。分析的向上柱体路径用屏幕 y 向下为正，因此更小的 P 代表更高的峰。

把当前柱顶变为相同内部坐标系后记为 Y，当前 GetTickCount 为 now：

1. 若 P≥Y：P←Y，v←a，t0←now。相等也刷新保持计时。
2. 否则，若无符号 32 位差值 now-t0 小于 Hold：不改变位置和步进。
3. 否则：P←P+v，然后 v←v+a。
4. 输出时 P 算术右移 8 位，并按 Bar mode 的掩码对齐；以两个相同 y 的端点调用 Polyline。

对应地址 0x10004814、0x10004817、0x1000481B–0x10004836、0x1000483B–0x1000486A、0x1000487C–0x10004899。

从最近一次重置算起，经历 n 次真正执行下落的更新后，在没有新峰干预时：

`P_n = P_0 + a*n*(n+1)/2`，像素位移为 `a*n*(n+1)/512`。

默认参数应用后的 a=36，10 次下落更新约 7.734 像素，20 次约 29.531 像素。不要把更新次数直接替换为实际经过时间：Hold 用时钟，下落用更新次数，绘图卡顿会影响实际速度。

### 5.3 细节与复现限制

- 主路径取时间一次供这一帧使用，而不是每个柱分别 GetTickCount。
- 保持时间从最近一次柱体追上峰值算起，平顶连续帧会不断重置。
- 峰值画的是一小段实线，不是粒子发射器。灰白细柱很窄时才视觉上呈小亮点。
- 原指令在入状态前还加上绘图区 top，出状态后又有坐标偏移。普通客户端 top=0 时上述公式直接成立；移植到非零局部原点应核对完整坐标链，不要擅自把此细节优化掉。
- 本节完整覆盖指定绘图路径的状态更新。其他旋转路径的正负号与端点顺序不在本轮逐条验证范围内。

## 6. 绘图、刷新与 64 位迁移含义

确认 GDI 画笔、Polyline、GradientFill、内存位图和 BitBlt 调用。DLL 还动态加载 ddraw.dll / DirectDrawCreateEx；资源明确存在 Sync with scanline 开关。其 2 ms 多媒体定时器用于额外同步路径，不能据此说频谱算法固定为 500 FPS；普通刷新设置走 SetTimer。

64 位重建不需要恢复每一段 CRT 或旧 SDK 的实现；需要重新接入目标宿主提供的音频及 Columns UI 接口，再保留本文识别的行为。真正决定“像原版”的部分包括：

1. 保留左右声道独立数据、Mirror 奇偶方向和分区栅格；
2. 保留频率映射的自适应锚点、bin 聚合 max 和精确截断顺序；
3. 按宿主实际频谱输入归一化选择幅度公式，不能盲用 old/new 的同名数字；
4. 保留峰值 1/256 像素状态、相等重置计时和逐更新加速；
5. 后续单独决定是否保留 scanline 同步，不把它混进幅度或峰值公式。

本轮没有检查当前 SDK 的全部 ABI，也没有构建 x64 工程，所以“可行”是算法和架构层面的判断，不是编译或目标程序验证结果。

## 7. 未确认项与后续验证规格

已还原正常路径的核心逻辑，但以下不能由当前证据冒充完成：

- 截图所用的准确预设、FFT mode、刷新间隔、峰值参数：单张图无法确定；本轮没读取用户运行配置。
- 自适应频率映射 k=0 特殊值、极窄窗口、无声道、整型溢出等边界。
- 所有旋转、Simple-antialiasing、Horizontal-antialiasing、Simple-line 的像素端点规则。
- 新 SDK 可视化流相对旧 SDK 的 FFT 窗函数、幅度归一化和浮点格式差异。
- 停止播放/无有效 chunk 时各模式是否清零或保留峰值，以及所有缓存重建路径。

若进入实现阶段，建议对照项目为：单左/单右单音识别镜像方向；扫频辨认 bin 合并与坐标；多个固定电平辨认幅度斜率；短音后静音辨认 Hold 和加速轨迹；不同窗口宽度辨认 P 量化；改变刷新间隔辨认逐帧而非逐秒更新。这里只记录验证规格，没有生成测试音、运行原插件或实施移植。

## 9. 代数推导复核要点

这里保留容易误读的 x87 栈检查点，便于以后复核；栈按 ST(0)、ST(1)… 从左到右写出。

### 幅度

- 0x10004225 前：old method 得到 [K,1,2]；new method 得到 [1,1,2]。
- old+log 经 0x10004231–0x10004239，把首项变成 ln(1+2K)。随后乘 R，FDIVR 100 得到归一化系数 B。
- 0x10004477 前的有效工作栈为 [0,1/4,2^-17,B,1,2]；其中首项 0 是循环临时项。
- new mode 的 0x1000448B `fstp st(5)` 后，工作栈变为 [1/4,2^-17,B,1,0]。
- new+log 保留 1/4 系数；new+非log 在 0x100044D4 装入 2/7。
- 0x100044DE 加上常数 1，随后与 0 比较。小于等于 0 的路径直接构造零；其余路径重算 max(A,2^-17) 的 log10 并乘 B。
- old 分支分别形成 B*A 或 B*ln(1+2A)。因此报告中的四种公式不是根据控件名称推测。

### 对数频率

- 0x1000B785 附近的栈可归纳为 [Q(k-1),ln(1025),D,1024,1]，Q(k) 已暂存。
- 0x1000B7F4–0x1000B821 的比较选择 max(m,S*m/D)，不是 min。误读这一比较会让低频密度重建错误。
- 0x1000B854–0x1000B87F 依次形成锚点后的两个坐标 F_m(k-1)、F_m(k)。
- `fabs` 后与 1 比较，`test ah,0x41; jp` 对有限数的“大于”结果跳往重设锚点的分支；等于 1 不走重设分支。
- 阈值判断针对连续像素距离，发生在按 P 取整之前；不能用柱宽 P 替代阈值 1。

### 构造默认颜色

0x1002169C–0x100216D7 给出 ForeGround1=#E4E4E4、ForeGround2=#202020、BackGround=#000000、Peak=#F5F5F5。它们和截图的黑底灰白风格一致，但只是程序构造默认值，不能证明截图使用了未经修改的颜色或渐变模式。
